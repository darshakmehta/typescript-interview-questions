### **Interface Segregation Principle (ISP)**

The **Interface Segregation Principle (ISP)** is one of the five SOLID principles of object-oriented design. It states that:

> **"A class should not be forced to implement interfaces it doesn’t use."**

In simpler terms, instead of having a large, monolithic interface, you should break it down into smaller, more specific interfaces so that classes only need to implement the methods that are relevant to them.

---

### **Learn the Problem**

#### **Why is ISP Important?**

- **Problem**: When a single interface has too many unrelated methods, classes that implement it are forced to provide implementations for methods they don’t need. This leads to bloated, inflexible, and error-prone code.
- **Example**: Consider a `Printer` interface with methods like `print()`, `fax()`, and `scan()`. If a class only needs to print, it shouldn’t be forced to implement `fax()` and `scan()`.

#### **Solution**:

- Split large interfaces into smaller, more specific ones.
- Classes should only implement the interfaces that are relevant to their functionality.

---

### **Practice Example**

Let’s refactor a `Printer` interface to follow the **Interface Segregation Principle**.

---

#### **Step 1: Problematic Implementation**

Here’s an example of a monolithic `Printer` interface that violates ISP:

```typescript
interface Printer {
  print(document: string): void;
  fax(document: string): void;
  scan(document: string): void;
}

class BasicPrinter implements Printer {
  print(document: string): void {
    console.log(`Printing: ${document}`);
  }

  fax(document: string): void {
    throw new Error('Fax not supported');
  }

  scan(document: string): void {
    throw new Error('Scan not supported');
  }
}

class AdvancedPrinter implements Printer {
  print(document: string): void {
    console.log(`Printing: ${document}`);
  }

  fax(document: string): void {
    console.log(`Faxing: ${document}`);
  }

  scan(document: string): void {
    console.log(`Scanning: ${document}`);
  }
}
```

#### **Why This Violates ISP**:

- The `BasicPrinter` class is forced to implement `fax()` and `scan()` methods it doesn’t need, leading to unnecessary code and potential errors.
- This design is inflexible and violates the principle of separation of concerns.

---

#### **Step 2: Refactor to Follow ISP**

To fix this, we can split the `Printer` interface into smaller, more specific interfaces.

##### **Step 2.1: Define Smaller Interfaces**

Create separate interfaces for each functionality:

```typescript
interface Printer {
  print(document: string): void;
}

interface Fax {
  fax(document: string): void;
}

interface Scanner {
  scan(document: string): void;
}
```

##### **Step 2.2: Implement Only Relevant Interfaces**

Now, classes can implement only the interfaces they need.

```typescript
class BasicPrinter implements Printer {
  print(document: string): void {
    console.log(`Printing: ${document}`);
  }
}

class AdvancedPrinter implements Printer, Fax, Scanner {
  print(document: string): void {
    console.log(`Printing: ${document}`);
  }

  fax(document: string): void {
    console.log(`Faxing: ${document}`);
  }

  scan(document: string): void {
    console.log(`Scanning: ${document}`);
  }
}
```

---

#### **Step 3: Test the Refactored Code**

Now, the `BasicPrinter` class only implements the `Printer` interface, and the `AdvancedPrinter` class implements all three interfaces.

```typescript
const basicPrinter = new BasicPrinter();
basicPrinter.print('Document 1'); // Works fine

const advancedPrinter = new AdvancedPrinter();
advancedPrinter.print('Document 2'); // Works fine
advancedPrinter.fax('Document 2'); // Works fine
advancedPrinter.scan('Document 2'); // Works fine
```

---

### **Key Takeaways**

1. **Interface Segregation Principle**: Break down large interfaces into smaller, more specific ones so that classes only implement what they need.
2. **Avoid Forcing Unnecessary Methods**: Classes should not be forced to implement methods they don’t use.
3. **Flexibility and Maintainability**: Smaller interfaces make your code more flexible, maintainable, and easier to extend.

By following ISP, you ensure that your code adheres to the principle of separation of concerns and is easier to work with. 🚀
