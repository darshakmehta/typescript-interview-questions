### **Liskov Substitution Principle (LSP)**

The **Liskov Substitution Principle (LSP)** is one of the five SOLID principles of object-oriented design. It states that:

> **"Subtypes should be substitutable for their base types without altering the correctness of the program."**

In simpler terms, if a class `B` is a subclass of class `A`, then you should be able to replace `A` with `B` without breaking the behavior of the program.

---

### **Learn the Problem**

#### **Why is LSP Important?**

- **Problem**: If a subclass changes the behavior of the parent class, it can lead to unexpected bugs when the subclass is used in place of the parent class.
- **Example**: Consider a `Rectangle` class with `setWidth` and `setHeight` methods. If you create a `Square` subclass that overrides these methods to enforce equal width and height, it violates LSP because a `Square` cannot substitute a `Rectangle` without breaking the expected behavior.

#### **Solution**:

- Ensure that subclasses adhere to the contract defined by the parent class.
- Avoid overriding methods in a way that changes the behavior of the parent class.

---

### **Practice Example**

Let’s refactor a `Rectangle`/`Square` class hierarchy to follow the **Liskov Substitution Principle**.

---

#### **Step 1: Problematic Implementation**

Here’s an example that violates LSP:

```ts
class Rectangle {
  protected width: number;
  protected height: number;

  constructor(width: number, height: number) {
    this.width = width;
    this.height = height;
  }

  setWidth(width: number): void {
    this.width = width;
  }

  setHeight(height: number): void {
    this.height = height;
  }

  getArea(): number {
    return this.width * this.height;
  }
}

class Square extends Rectangle {
  constructor(size: number) {
    super(size, size);
  }

  setWidth(width: number): void {
    this.width = width;
    this.height = width; // Enforces equal width and height
  }

  setHeight(height: number): void {
    this.height = height;
    this.width = height; // Enforces equal width and height
  }
}
```

#### **Why This Violates LSP**:

- A `Square` is a special case of a `Rectangle`, but it changes the behavior of `setWidth` and `setHeight` to enforce equal width and height.
- If a `Square` is used in place of a `Rectangle`, it can lead to unexpected behavior. For example:

```ts
function increaseRectangleWidth(rectangle: Rectangle): void {
  rectangle.setWidth(rectangle.width + 1);
}

const rectangle = new Rectangle(5, 10);
const square = new Square(5);

increaseRectangleWidth(rectangle);
console.log(rectangle.getArea()); // Expected: 55 (5 * 11)

increaseRectangleWidth(square);
console.log(square.getArea()); // Expected: 30 (5 * 6), but actual: 36 (6 * 6)
```

The `Square` subclass breaks the expected behavior of the `Rectangle` class.

---

#### **Step 2: Refactor to Follow LSP**

To fix this, we can avoid using inheritance and instead use composition or a shared interface.

##### **Option 1: Use a Shared Interface**

Define a `Shape` interface and implement it separately for `Rectangle` and `Square`.

```ts
interface Shape {
  getArea(): number;
}

class Rectangle implements Shape {
  private width: number;
  private height: number;

  constructor(width: number, height: number) {
    this.width = width;
    this.height = height;
  }

  setWidth(width: number): void {
    this.width = width;
  }

  setHeight(height: number): void {
    this.height = height;
  }

  getArea(): number {
    return this.width * this.height;
  }
}

class Square implements Shape {
  private size: number;

  constructor(size: number) {
    this.size = size;
  }

  setSize(size: number): void {
    this.size = size;
  }

  getArea(): number {
    return this.size * this.size;
  }
}
```

##### **Option 2: Use Composition**

Instead of inheriting from `Rectangle`, the `Square` class can use a `Rectangle` internally.

```ts
class Rectangle {
  protected width: number;
  protected height: number;

  constructor(width: number, height: number) {
    this.width = width;
    this.height = height;
  }

  setWidth(width: number): void {
    this.width = width;
  }

  setHeight(height: number): void {
    this.height = height;
  }

  getArea(): number {
    return this.width * this.height;
  }
}

class Square {
  private rectangle: Rectangle;

  constructor(size: number) {
    this.rectangle = new Rectangle(size, size);
  }

  setSize(size: number): void {
    this.rectangle.setWidth(size);
    this.rectangle.setHeight(size);
  }

  getArea(): number {
    return this.rectangle.getArea();
  }
}
```

---

#### **Step 3: Test the Refactored Code**

Now, the `Rectangle` and `Square` classes are independent and do not violate LSP.

```ts
const rectangle = new Rectangle(5, 10);
const square = new Square(5);

rectangle.setWidth(6);
console.log(rectangle.getArea()); // Expected: 60 (6 * 10)

square.setSize(6);
console.log(square.getArea()); // Expected: 36 (6 * 6)
```

---

### **Key Takeaways**

1. **Liskov Substitution Principle**: Subclasses should be substitutable for their base classes without altering the correctness of the program.
2. **Avoid Inheritance When It Breaks LSP**: If a subclass changes the behavior of the parent class, consider using composition or a shared interface instead.
3. **Design for Flexibility**: Ensure that your class hierarchy adheres to LSP to make your code more robust and maintainable.

By following LSP, you ensure that your code is more predictable and easier to extend without introducing bugs. 🚀
